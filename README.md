# 毎日就活：Codex運用仕様

日々の使い方は [運用ガイド.md](運用ガイド.md) を参照。

## リポジトリの操作範囲

- `sandbox`／`サンドボックス`という名前または用途のリポジトリには、ファイル変更、ステージ、コミット、pushなどの操作を一切行わない。
- このプロジェクトの変更をコミット／pushする場合は、ユーザー個人の指定リポジトリ `aoiseki0415/Evryday_Syukatsu` のみを対象とする。
- 操作前にGitのremote URLを確認し、指定リポジトリと一致しない場合は処理を中止してユーザーへ確認する。

## 目的

毎日の自由記述を一度だけ保存し、内容に応じて企業分析・自己分析の情報として Notion に整理する。

## Notion の構成

- **毎日就活**：記録の正本。カレンダー表示を使う。
- **企業ページ**：該当企業に紐づいた毎日就活の記録をテーブルで表示する。
- **自己分析ページ**：自己分析に分類された毎日就活の記録をテーブルで表示する。

同じ内容を複数のデータベースにコピーしない。毎日就活の記録を一件だけ作り、企業・自己分析側はその記録を絞り込んで表示する。

## 毎日就活の記録項目

- **タイトル**：ユーザーのひとこと（Notion の必須タイトル欄を使用）
- **日付**：記録日
- **分類**：`企業分析`、`自己分析`（複数選択可）
- **企業**：企業研究データベースの企業への複数リレーション
- **企業名（表示用）**：各企業ページのテーブルを絞り込むために Codex が設定する補助項目

## Codex の処理

このチャットには、予定済みタスクにより毎日23:00（日本時間）にCodexから次のメッセージが送られる。

> 就活に関わる今日の振り返りを送ってください

研究者であるユーザーは、このメッセージに対して当日の就活の振り返りを文章で送る。リマインダーに関係なく送られた通常の自由記述も、その日の就活メモとして扱う。

1. ユーザーから自由記述を受け取る。
2. 内容を短く要約し、分類（企業分析／自己分析）と対象企業を推定する。複数企業を検出した場合はすべて候補にする。
3. 保存前に必ず確認する。例：

   > 「KPMG／企業分析・自己分析として保存しますか？」

   確認には必ず、Notionカレンダーへ登録する**記録日**も含める。

4. ユーザーが明示的に保存を承認した場合のみ、毎日就活に一件作成する。
5. 選んだ企業をリレーションに設定する。企業が複数なら一件の記録に複数社を紐づける（内容を複製しない）。
6. 自己分析が選ばれた場合、自己分析ページの毎日就活テーブルに自動表示される状態にする。
7. 企業分析が選ばれた場合、各企業ページの毎日就活テーブルに自動表示される状態にする。
8. 保存した記録日が日曜日の場合のみ、保存後に週間振り返りを行う。
9. Notionへの記入・保存確認などの一連の工程が終了したら、Apple純正「リマインダー」の実行済み処理についてユーザーへ確認する。日曜日は週間振り返りも終えてから確認する。
10. ユーザーの許可後にApple純正「リマインダー」をComputer Useで操作する場合は、操作を始める直前に必ず `caffeinate -u -t 600 &` をバックグラウンド実行する。このディスプレイ起動・維持処理と、Computer Useの開始について追加の承認は求めない。
11. コマンド実行後、対象アプリを変更する操作へ進む前に、読み取り専用の状態取得でディスプレイが起きてMacを操作できる状態であることを確認する。確認できない場合はComputer Useによる操作を行わず、その段階でユーザーへ状況を報告する。

## 日曜日の週間振り返り

日曜日は、通常の日次処理を完了し、その日の記録がNotionへ正しく保存されたことを確認した後に、次のやり取りを追加する。

1. Notionの正本「毎日就活」から、その週の月曜日から日曜日までの記録を参照する。
2. 各日の記録内容を、月曜日から日曜日の順に1日ずつ簡潔な箇条書きでまとめる。記録がない日は「記録なし」と明記する。
3. 次の言葉から週間フィードバックを開始する。

   > この1週間を振り返りましょう

4. 日別の要約に続けて、1週間を通じた取り組み、気づき、企業分析・自己分析の傾向を簡潔にフィードバックする。

週間振り返りはNotionに保存済みの記録を根拠に作成する。日曜日の日次記録を保存する前に開始せず、週間フィードバック自体を新しい日報として自動保存しない。

## Apple「リマインダー」の実行済み処理

Notionへの記入と保存確認を含む一連の工程が終了したら、Codexは必ず次のように尋ねる。

> リマインダーを実行済みにして良いですか

ユーザーが明示的に許可した場合に限り、Apple純正「リマインダー」アプリのリスト「Daily To Do」にある「毎日就活」というリマインダーを実行済みにする。

- 許可を得る前にリマインダーを操作しない。
- 操作対象は「Daily To Do」リスト内の「毎日就活」のみに限定する。
- 行ってよい操作は、その対象を**実行済みにすることだけ**とする。
- リマインダーの作成、編集、名称変更、移動、削除、日時変更、繰り返し設定の変更、ほかのリマインダーの操作は行わない。
- 対象が見つからない、同名の候補が複数ある、または対象を一意に確認できない場合は操作せず、ユーザーへ報告する。

## Computer Use開始前のディスプレイ維持

このプロジェクトでComputer Useを使う場合は、Computer Useの最初の操作より前に、必ず次のコマンドをバックグラウンド実行する。

```sh
caffeinate -u -t 600 &
```

- `-u`によりユーザーが操作中であることをmacOSへ通知する。ディスプレイがオフなら点灯し、アサーションが有効な間はアイドルによるディスプレイスリープを防ぐ。
- `-t 600`によりアサーションは600秒（10分）で解除される。
- ディスプレイの起動・維持コマンドの実行、およびComputer Useの開始について、ユーザーへ追加の承認を求めない。
- コマンド実行後、対象アプリを変更する操作の前に、読み取り専用の状態取得でディスプレイが起きてMacを操作できる状態であることを確認する。
- ディスプレイが起きない、Macがロックされている、または操作可能な状態を確認できない場合は、その先のComputer Use操作へ進まず、直ちにユーザーへ状況を報告する。ロック解除や回避操作は試みない。
- このコマンドは10分を超えるComputer Use、手動ロック、またはほかの要因によるロックを防ぐことまでは保証しない。
- 10分を超えてComputer Useを継続する必要がある場合は、期限が切れる前に同じコマンドを再実行してから操作を続ける。
- Computer Useを使用しない処理では実行しない。

## 初登場の企業

対象企業が企業研究データベースに存在しない場合は、勝手に作らない。必ず次を確認する。

> 「○○を企業研究に新規作成し、今回の記録を紐づけますか？」

ユーザーが承認したら、既存の企業ページ用テンプレートで企業レコード／ページを作成し、そのページに「毎日就活」のテーブル表示を追加する。その後、今回の記録を紐づける。

## 方針

- 分類・企業名の推定は Codex が行うが、保存と新規企業作成は必ずユーザー確認後に実行する。
- 日報データは毎日就活を唯一の正本とする。
- 企業ページと自己分析ページは、正本のテーブル表示として扱う。
- ユーザーは日々の自由記述だけを送る。Codex は分類、対象企業の抽出、保存前の確認、Notionへの反映を担当する。

## Notionの編集範囲

- Codexが編集してよいのは、ユーザーが保存を承認した「毎日就活」の日次記録と、その記録を表示するために必要な承認済みの企業ページ・自己分析ページへの紐づけに限る。
- 初登場企業の作成や企業ページへの「毎日就活」テーブル追加は、個別にユーザーの承認を得た場合のみ行う。
- 上記以外のNotionページ、データベース、プロパティ、ビュー、テンプレート、本文、設定は、ユーザーから明示的な指示と承認がない限り編集・作成・移動・削除しない。
- 必要な情報を参照する場合も、作業に必要な最小範囲に限定し、参照しただけのページを変更しない。

## 記録日の扱い

- 毎晩23:00の予定済みメッセージに対する回答は、実際の送信時刻が日付をまたいでも、**メッセージが届いた日**を記録日とする。例：8月5日23:00のメッセージに対し、8月6日0:30に回答した場合は、8月5日のカレンダーへ保存する。
- 次の23:00の予定済みメッセージ以後の回答は、その新しいメッセージが届いた日を記録日とする。
- リマインダーに紐づかない通常の記録は、日本時間での送信日を記録日とする。
- 保存確認では、分類・対象企業に加えて「記録日：YYYY年M月D日」を必ず明示する。
