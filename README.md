# 毎日就活：Codex運用仕様

日々の使い方は [運用ガイド.md](運用ガイド.md) を参照。

## リポジトリの操作範囲

- `sandbox`／`サンドボックス`という名前または用途のリポジトリには、ファイル変更、ステージ、コミット、pushなどの操作を一切行わない。
- このプロジェクトの変更をコミット／pushする場合は、ユーザー個人の指定リポジトリ `aoiseki0415/Evryday_Syukatsu` のみを対象とする。
- 操作前にGitのremote URLを確認し、指定リポジトリと一致しない場合は処理を中止してユーザーへ確認する。

## 目的

毎日の自由記述を一度だけ保存し、内容に応じて企業分析・自己分析の情報として Notion に整理する。

## Notion の構成

- **毎日就活**：記録の正本。カレンダー表示を使う。
- **企業ページ**：該当企業に紐づいた毎日就活の記録をテーブルで表示する。
- **自己分析ページ**：自己分析に分類された毎日就活の記録をテーブルで表示する。

同じ内容を複数のデータベースにコピーしない。毎日就活の記録を一件だけ作り、企業・自己分析側はその記録を絞り込んで表示する。

## 毎日就活の記録項目

- **タイトル**：ユーザーのひとこと（Notion の必須タイトル欄を使用）
- **日付**：記録日
- **分類**：`企業分析`、`自己分析`（複数選択可）
- **企業**：企業研究データベースの企業への複数リレーション
- **企業名（表示用）**：各企業ページのテーブルを絞り込むために Codex が設定する補助項目

## Codex の処理

このチャットには、予定済みタスクにより毎日23:00（日本時間）にCodexから次のメッセージが送られる。

> 就活に関わる今日の振り返りを送ってください

研究者であるユーザーは、このメッセージに対して当日の就活の振り返りを文章で送る。リマインダーに関係なく送られた通常の自由記述も、その日の就活メモとして扱う。

1. ユーザーから自由記述を受け取る。
2. 内容を短く要約し、分類（企業分析／自己分析）と対象企業を推定する。複数企業を検出した場合はすべて候補にする。
3. 保存前に必ず確認する。例：

   > 「KPMG／企業分析・自己分析として保存しますか？」

   確認には必ず、Notionカレンダーへ登録する**記録日**も含める。

4. ユーザーが明示的に保存を承認した場合のみ、毎日就活に一件作成する。
5. 選んだ企業をリレーションに設定する。企業が複数なら一件の記録に複数社を紐づける（内容を複製しない）。
6. 自己分析が選ばれた場合、自己分析ページの毎日就活テーブルに自動表示される状態にする。
7. 企業分析が選ばれた場合、各企業ページの毎日就活テーブルに自動表示される状態にする。

## 初登場の企業

対象企業が企業研究データベースに存在しない場合は、勝手に作らない。必ず次を確認する。

> 「○○を企業研究に新規作成し、今回の記録を紐づけますか？」

ユーザーが承認したら、既存の企業ページ用テンプレートで企業レコード／ページを作成し、そのページに「毎日就活」のテーブル表示を追加する。その後、今回の記録を紐づける。

## 方針

- 分類・企業名の推定は Codex が行うが、保存と新規企業作成は必ずユーザー確認後に実行する。
- 日報データは毎日就活を唯一の正本とする。
- 企業ページと自己分析ページは、正本のテーブル表示として扱う。
- ユーザーは日々の自由記述だけを送る。Codex は分類、対象企業の抽出、保存前の確認、Notionへの反映を担当する。

## 記録日の扱い

- 毎晩23:00の予定済みメッセージに対する回答は、実際の送信時刻が日付をまたいでも、**メッセージが届いた日**を記録日とする。例：8月5日23:00のメッセージに対し、8月6日0:30に回答した場合は、8月5日のカレンダーへ保存する。
- 次の23:00の予定済みメッセージ以後の回答は、その新しいメッセージが届いた日を記録日とする。
- リマインダーに紐づかない通常の記録は、日本時間での送信日を記録日とする。
- 保存確認では、分類・対象企業に加えて「記録日：YYYY年M月D日」を必ず明示する。
