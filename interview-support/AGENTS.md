# この領域で作業するCodexへ

- 最初にSTART_HERE → SPEC → OPERATIONS → ROADMAP → learning/READINESSを読む。4領域の保管情報はINFORMATION_MAPを参照する。
- ①は解法に沿った回答全体を導く能力、②はその一部の初手提示と本人の現在地への適応。Codexの分析を初手で止めない。
- ケース/フェルミの各solve・supportにinput・学習・CURRENTを分ける。①は問題集・解答・解説等で評価し、本人に正誤判定を求めない。十分な精度の根拠がそろってから②へ進み、②で本人のフィードバックを使う。
- ①未評価のまま②を並行して試す提案は採用されていない。自信や解説の暗記だけで高精度とせず、READINESSへ評価範囲と未解決点を記録する。
- ケース内の推定はケースモードのまま。単独フェルミモードは推定そのものが単独出題された場合のみ。共通知識・教材・探索経路を参照で共有する。
- 本番準備はreadyに従い①②の現行本文を読む。支援はWorkの会話で行い、アプリ開発を開始しない。現在は教材未登録・学習未実施・本番未準備。
- 編集はinterview-support/と指定Notionホーム配下のみ。親のHANDOFF・ログ等も勝手に更新しない。Git対象確認・公開範囲・既存変更保護は親規則を継続する。
- 現行確定・議論・過去・提案・実践の証拠を分け、節目ごとに細かく保存する。Notionは本人向けに図・表で最新の要点と構造を示す。
- 指示済みの調査・整理・更新・支援に追加承認を求めない。まだ開始しないと指示された収集・演習は実行しない。強制的な権限手続きは回避しない。
- 終了前に記録・現行正本・Notion要約の整合、読み戻し、関連ファイルだけの差分確認・コミット・push・remote一致確認を行う。未確認は明記する。

- 情報管理はDOCUMENTATIONを読む。成果の本文はdetails、全項目はINDEXへ。A/B/Cと状態を分け、採用済みAだけCOREへ要約し、議論・変更はHISTORYから日付付きlogsへ。未学習の中身を作らない。
