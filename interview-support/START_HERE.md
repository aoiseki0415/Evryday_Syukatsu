# 新しいWorkチャットの入口

本人が「ケース面接サポートをして」「フェルミ推定サポートをして」と依頼したら、ここから再開する。アプリを作成・起動する手順ではない。

## 起動手順

1. 親AGENTSに従いGitルート・branch・origin・作業状態を確認し、git pull --ff-only origin mainを行う。取得できなければ最新と断定しない。
2. [SPEC](SPEC.md)と[OPERATIONS](OPERATIONS.md)で目的・境界・準備状態を把握する。
3. 次の分岐でモードを選ぶ。明確な依頼を承認の質問で聞き直さない。

| 依頼・出題の性質 | 読む文書 |
| --- | --- |
| ケース面接。課題の一部に数量推定が含まれても同じ | [ケース面接の手順](modes/case/PLAYBOOK.md) |
| フェルミ推定そのものが単独で課される | [単独フェルミ推定の手順](modes/fermi/PLAYBOOK.md) |
| 仕組み・知識・学習運用の検討 | SPEC・OPERATIONS・関連共通基盤とログ |

4. [learning/CURRENT](learning/CURRENT.md)と参照される知識、継続中なら前回sessionを読む。必要な資料だけ追加でたどる。
5. 問題・時間・制約等が不足していれば、情報不足の確認として簡潔に尋ねる。既に条件があればそのまま進める。
6. PLAYBOOKの準備状態を確認する。未策定なら決定済みの手順で支援できると装わず、未策定と短く伝える。本人が求める暫定支援は正式採用済みの手順と区別する。

## 支援中・終了時

ケース内の推定ではモードを変えず共通知識を使う。情報探索はshared/research、実践記録はsessions、改善の経緯はlearning、採用した内容は現行の手順・知識に反映する。本人に毎回過去の議論を貼り直してもらわず記録から復元し、復元できない情報を分かったふりで補わない。
