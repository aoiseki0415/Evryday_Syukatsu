# 2026-11-25 優先度と文書の役割・環境整備

出典：本チャットの本人指示。4領域の議論は[前段ログ](2026-11-25-four-track-learning.md)。

## 確定した方針

- inputと学習で得たケース①②・フェルミ①②の情報をGitHubとNotionへ構造化して保存する。
- 重要な情報の要約、全情報を重み順にたどる索引、種類別の本文、議論・変更の履歴を目的別に分ける。
- 提案したA必須/B重要/C補足、優先度と確からしさの別管理、本文・要約・索引を参照で結ぶ方針を本人が了承。
- 今回は土台と運用仕様・構造を整備する。未学習の解法・数値・施策・成果は書かない。
- 指示済み作業の追加承認は求めず、コミット・pushと反映確認まで完了する。

## 中断と再開

前段のローカル文書は、本人の「まだ対応しない、方針検討のみ」で保留し、コミット・push・Notion更新はしなかった。今回の環境整備の指示で再開し、保留中の変更と新しい優先度方針を照合して仕上げる。

## 実装判断

各領域にCORE、INDEX、details、HISTORYを作成。INPUT・LEARNINGと用途を分け、CURRENTは現行文書への入口とした。DOCUMENTATIONに定義・更新手順・読む方法、templatesに未記入の形式を置く。これは文書構造の判断であり、知識・学習成果の登録ではない。

①を教材で十分に高精度へ→②を本人のフィードバックで調整する順序を維持する。

## 実施と検証

GitHub・Notionの構造更新と確認結果を、作業の節目で追記する。編集はinterview-support/と指定Notionホーム配下だけ。

### GitHub

- 4領域それぞれにINPUT、LEARNING、CORE、INDEX、details、HISTORY、CURRENTの入口を整備。重要要約・全情報索引・種類別本文・変更記録を分離し、学習情報は全領域で未登録と表示した。
- SPEC、OPERATIONS、START_HERE、AGENTS、INFORMATION_MAP、ROADMAP、READINESS、readyを整合。①の全体回答、教材評価、十分な精度確認後の②、本人の支援品質評価を区別した。
- DOCUMENTATIONにA/B/C・状態・優先度変更・要約/索引/本文の更新手順を記録。templatesは未記入の形式のみ。原資料台帳、共通知識・探索経路は中身を追加していない。
- 過去の経緯は旧ログと固定コミットへ保持。①の採点を本人へ依頼する旧記述や、①未評価のまま②を進める提案は現行の方針として使わない。
