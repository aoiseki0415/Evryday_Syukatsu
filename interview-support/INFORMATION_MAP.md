# 保管すべき情報：4領域の情報設計

更新：2026-11-25。これは保管対象の設計であり、以下の解法・数値・教材を収集・検証済みという意味ではない。現行情報の入口は各CURRENT。重み付けと文書の役割は[DOCUMENTATION](DOCUMENTATION.md)。

## ケース①：問題全体を解く

保存先：[solve](modes/case/solve/README.md)。

- **問いの分類と解法**：何を求める問題か、選べる解法、選ぶ条件、使えない場面、異なる解法の比較。理想・現状・ギャップ・原因・施策の型を全問に固定しない。
- **回答全体の構成**：目的・制約、与件と現状、必要な分析、問題特定、原因仮説と根拠、必要な定量化、施策、効果・実現性・費用等の比較、結論までのつながり。問題に必要な構成を選ぶ。
- **知識・施策の引き出し**：事業や顧客等の理解、施策と対応する課題・原因、作用の仕組み、成立条件、効果、限界、リスク、企業事例の認識・対応・成果・課題。単なる施策名の一覧で終えない。
- **根拠と検証**：事実/仮定/推測、統計・資料の定義と時点、因果の留保、計算、反対仮説、実行可能性、結論との整合。教材の説明とCodexの追加解釈を区別する。
- **教材と学習成果**：問題・解答・解説の参照先、全体回答、採点観点ごとの照合、見落とし、誤った解法の選択、修正、未見問題の結果、採用ルールの適用条件と例外。

## フェルミ①：問題全体を解く

保存先：[solve](modes/fermi/solve/README.md)。

- **問いの分類と解法**：推定対象の定義、量・範囲・期間・単位、適した分解・推定方法、候補式、選ぶ根拠、重複・漏れの防止、使えない条件。
- **ラフな前提知識**：本番で使う概数、単位・地域・対象年・定義、使える状況、元になる確認値・出典、丸め方、範囲・不確実性。人口等は精密な統計表を覚えることと、概数で解くことを分ける。
- **数字を合理的に設定する方法**：[number-setting-methods](modes/fermi/solve/details/number-setting-methods.md)。同条件の既知情報、観察/経験の母集団補正、集団/購入構成の加重、類推、行動/時間/物理制約、範囲からの代表値、検算。選択条件と不適用を保存する。
- **数字設定の参照索引**：[references](modes/fermi/solve/references/NUMBER_INDEX.md)。ネット上と過去演習の設定値、分母/単位/期間、根拠の種類、元条件、補正と使用不可、原記録を保存。基礎前提知識とは分け、妥当性照合/導出困難時の補助に使う。
- **全体回答**：前提、分解式、各変数と仮定、代入、途中と最終の計算、結果と単位、桁・上限下限・別の見積もり等による妥当性確認、変えたときの影響。
- **教材と学習成果**：問題・解説の参照先、全体回答、分解や仮定・式・計算・単位・妥当性の照合、誤差要因、訂正、未見問題の結果、再利用できるルールと例外。解答例と同じ数字になったかだけで評価しない。

## ケース②：本人へ支援する

保存先：[support](modes/case/support/README.md)。①の解法・知識は参照し、ここで別体系として複製しない。学習は①の十分な精度を確認してから。

- **入力の扱い**：文字/スクショの読取、与件・図表・単位・制約、読めない条件の扱い。
- **初手の切り出し**：全体回答のどこをきっかけとして出すか、問いによる範囲の違い、短い表現、並び、図表や箇条書きの使い方、伝えすぎ・省略しすぎの防止。
- **途中からの支援**：本人から共有された現在地・真因・変更条件、不明な条件、施策依頼等への応答、当初の全体回答を修正した理由。本人の未共有の思考を捏造しない。
- **本人による評価と改善**：すぐ認識できたか、誤解がなかったか、適切な範囲か、使える速さか、現在地に合ったか。提示前後の比較と採用ルール。

## フェルミ②：本人へ支援する

保存先：[support](modes/fermi/support/README.md)。最新の本人指示で開始済み。①全体精度未認定は維持する。ノータイム前提、上位の[workflow](modes/fermi/support/details/workflow.md)から、準備と初回共有を独立した本文へ案内する。

- **準備時の確認**：[preparation](modes/fermi/support/details/preparation.md)。①②の読む順、全索引/本文への経路、優先度/採否/条件、最新訂正/探索経路、準備完了条件。
- **お題受領から初回共有**：[initial-response](modes/fermi/support/details/initial-response.md)。文字/スクショから対象/期間/単位/制約を読み、型選択と全体回答を①で構築/確認し、対象/結果→日本語式→代入→短い式理由/各数字理由を提示。速度/モデル方針と実測を分ける。
- **追加依頼への対応**：初回後の突然の質問は後日議論し、今回具体的ルールを制定しない。実際の別解応答は証拠としてのみ保存する。
- **本人による評価と改善**：式と仮定を即座に把握できたか、誤読がないか、速さ、修正のしやすさ、不要な説明の有無。実際の評価を保存する。

## 全領域で結ぶ情報

| 種類 | 保管・参照先 | 共通メタデータ |
| --- | --- | --- |
| 原資料・問題集 | shared/materialsの台帳、元の非公開資料 | source_id、所在、問題番号、解答/解説の有無、利用範囲 |
| 資料読解・複数資料の比較 | 各領域input、INPUTから参照 | note_id、source_id、読解範囲、共通点/相違点、統合判断、未解決点 |
| 再利用する解法・知識 | 各領域details、共通知識はshared/knowledge。INDEXから全件参照 | knowledge_id、A/B/Cと理由、出典/時点、モード・①②、選択/適用条件、状態・使用版 |
| 演習・照合 | 各領域learning | exercise_id、教材/問題ID、解答閲覧前の回答、照合根拠、結果、使用版 |
| 採用済み改善 | 各details、INDEXとCOREから参照 | rule_id、優先度と理由、状態、内容、根拠、検証範囲、反映先、失効/後継 |
| 準備セット | ready | 上記の現行版・読む順・不足・準備状態 |
| 必要時の探索 | shared/research | 質問の種類、到達先、検索語、確認項目、代替経路、確認日 |
| 調査・学習の範囲と再開点 | learning/COVERAGE・CYCLES、サイクルの実記録 | 情報種類/問題型、inputと演習の対応、更新情報ID、残る弱点、次の作業 |

本番や②の対話記録はsessionsを正本にし、学習記録から参照する。同じ回答・対話を全文で二重保存しない。①の演習記録は各solve/learningが正本。著作権・公開範囲に配慮し、問題集の非公開本文・解説全文を公開GitHubへ複製せず、問題IDと所在、自作の回答・分析を記録する。

教材への依存がない自己流の高評価だけを、正確さの根拠にしない。根拠が不足した記録は未評価と表示する。

## ①で性質を混同しない情報

**解法・概数・施策等の再利用本文／資料の読解と比較／各問題の全体回答・評価・修正／採用判断・議論と変更履歴**を分け、IDと参照で結ぶ。演習から得た改善は根拠を演習記録に残し、一般化できる内容だけを適用条件付きでdetailsへ整理する。

解法には問題型に応じて何を選ぶか・切り替えるかも含む。①の品質情報には、全体回答の正確さ・妥当性・未評価点に加え、計測できた作成時間と探索/待ちの影響も含む。②の本人向け出力形式や理解速度とは分ける。実行手順は[SOLVE_WORKFLOW](learning/SOLVE_WORKFLOW.md)。
