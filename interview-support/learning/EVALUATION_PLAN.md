# ①の版を固定して確かめる未見評価

2026-11-25、EVAL-BATCH-001の**問題選択・閲覧前**に設定。過去の新規学習問題は解説前に解いたが、手法更新に使っており未見評価の証拠とは別にする。①全体の十分な精度の正本は[READINESS](READINESS.md)。

## 固定と選び方

1. 初期input→複数型演習→差分の再input→転用を終えた標準手順v2を保存・commitし、そのSHAと使用ID/版を記録する。
2. その後で、既読のお題/解説と重ならないケース4問・フェルミ4問を選ぶ。CaseMatchのオリジナル問題各2、ジムの未読題各2を目安に両教材を使う。同じ問題の引き直しは復習とし、新規数へ加えない。
3. CaseMatchは問題/必要条件だけを先にもらい、解説/評価/採点は初回答固定後。お題が過去問題と同一・細部変更だけなら除外して理由を記録する。自由推定/仮説型と与件が閉じた検算型を区別する。
4. この8問の回答が揃うまで、参照解答を読まず手順の更新も保留。既存v2の必要箇所を読むことと、当該問題の答えを調べることを分ける。外部事実がなければ条件付き仮定を使い、その限界も評価する。

## 評価観点（結果を見て緩めない）

SOLVE-CYCLE-001の6観点を継続：対象/条件、方法/構造、仮定と根拠、計算と単位/定量比較、結論/実現性、妥当性/反証と感度。各問で「十分/要改善/重大な不足/評価不能」と理由を付ける。

- **重大な不足0**を必須とする。対象違い、主要な漏れ/二重計上、結論を変える計算ミス、事実の創作、制約違反、原因に対応しない施策は重大。参照値との合理的仮定差だけでは重大としない。
- 設問が要求する全体回答を完了し、代替案/条件付き結論・反証を残す。数値が全て与えられる問題は計算/条件の整合が必要。自由仮定型は、最終値一致ではなく各係数の説明・主要感度・容量/別経路との整合を確認する。
- 対象/構造/計算/結論に要改善以上の不足があれば、その型の評価を完了扱いにしない。根拠・検証の要改善は具体的な残課題として残し、精度達成の主張へ混ぜない。
- AI講評、解説との自己比較、算術による確認を区別。AIが肯定しても、数式・与件の矛盾をそのまま採用しない。点数/正答率を新しく創作しない。
- 速度は測れた範囲だけ記録する。複数問の並行処理・他作業を挟んだ時間を1問の応答時間とせず、未計測を補わない。本番の体感速度と②の提示評価は未実施。

問題ごとの結果・修正前後・版を保存してから手順を更新する。失敗した型を新しい別問題で再評価し、既読の答え直しを新規合格へ数えない。8問の一回だけで全ケース/全フェルミの完成としない。②移行には、未評価の型・重大誤りの再発・必要な根拠と速度をREADINESSで別途判断する。
