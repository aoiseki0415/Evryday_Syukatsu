# 学習の全体索引と運用

現行の主軸はケース/フェルミ × ①solve/②supportの4領域。input・演習・評価・採用済みの改善を各領域で分ける。原則①の精度確認を先行するが、後続の本人指示によりフェルミ②は開始済み。ケース②は未開始、①全体精度未認定は維持する。

①の作業開始は[実行仕様](SOLVE_WORKFLOW.md) → [情報種類・問題型のカバレッジ](COVERAGE.md) → [サイクル索引・再開点](CYCLES.md)。広いinputと資料比較、知識の実適用による演習・照合・更新を繰り返し、使用版と更新の対応を残す。記録は[ひな形](../templates/README.md)を使う。

①は問題集・解答・解説等で学習・照合し、本人を正誤の採点役にしない。②は①の回答全体を土台に、本人が使いやすい提示・途中依頼への適応を評価する。

実際の①演習は各solve/learningに記録。②の対話はsessions、評価・改善は各support/learningへ参照で結ぶ。採用した内容の本文はdetails、全項目はINDEX、重要な採用済みAはCOREへ。CURRENTはそれらの入口。ここへ同じ履歴を複製しない。

[READINESS](READINESS.md)が①の精度と②への移行の状態の正本、[CURRENT](CURRENT.md)が4領域の現行索引。[演習台帳](EXERCISES.md)で操作試行・学習・復習・未見評価と実際の問題数を区別する。CaseMatch文字AIとケース面接ジムを同等の主要演習先とする。現在のフェルミ作業は数字設定方法/参照例の調査と過去演習再検討であり、新規問題は解かない。学習は文書・知識・手順の更新と次回適用を意味し、モデル自体の追加訓練や全型の精度向上の実証を意味しない。
