# 支援システムの現行仕様

更新：2026-11-25（全体像・運用の確定）。本人の最新指示を反映した現在の正本。経緯は[ログ](logs/2026-11-25-project-direction.md)、旧版は[archive](archive/README.md)。

## 目的・利用イメージ

アプリではなく、Codexとの会話で支援する仕組みを、運用文書・知識・学習記録で再現できるようにする。

このプロジェクトで新しいWorkチャットを開く → 支援の種類を短く伝える → Codexが指定文書・採用済みの学びを読む → 事前に決めた手順でWork上の対話支援を行う。本人が毎回、方法や蓄積を説明し直す必要がない状態を目指す。

## 2モードと共通基盤

| 項目 | ケース面接サポート | フェルミ推定サポート |
| --- | --- | --- |
| 適用 | ケース面接の課題 | 推定そのものが単独で課される場合のみ |
| 推定の位置づけ | ケースを解くための手段として利用可 | 推定問題そのものを扱う |
| ケース内で推定する場合 | ケースモードを維持 | このモードに自動で切り替えない |
| 手順の正本 | [case/PLAYBOOK](modes/case/PLAYBOOK.md) | [fermi/PLAYBOOK](modes/fermi/PLAYBOOK.md) |

両者は完全独立ではない。共通の解法・前提知識・調査経路・演習からの学びを共有し、適用モードと条件を明記する。同じ知識を2か所で別々に更新しない。

## 最重要：問題とフィードバックから学ぶ

**input → 問題に取り組む → 回答例・フィードバックとの照合または本人との共同検討 → 改善を検証・記録 → 次回の支援へ反映**。

- 後で公開の練習問題と本人が登録しているサイトを活用する。
- 解法や知識の収集だけで完了にしない。実践を通じてCodexの回答・サポート精度を高めることが中心目的。
- 回答や評価を得られる場合は照合する。得られない場合は本人と一緒に解法を検討する。未評価を検証済みとしない。
- 改善は根拠となるセッション・評価とひも付け、採用した内容を現行手順・知識・学びへ反映する。後続のCodexが同じ理解で参照できる状態を目指す。
- 「学習」は知識・手順・評価の記録を後続の支援へ適用する運用。モデル自体の追加訓練や、精度向上の実証とは区別する。

## 後で整備するinputと探索経路

| 領域 | 対象 | 保存先 |
| --- | --- | --- |
| 両モード | 解法、考え方、適用条件、注意点 | モード別手順、shared/knowledge |
| フェルミ推定 | 人口等の前提知識。値・単位・地域・対象年・定義・出典 | shared/knowledge |
| ケース面接 | 施策例、成立条件、効果・限界、企業の実例 | shared/knowledge |
| 必要時の情報 | 日本政治・国際情勢・環境問題の実情、企業の認識・対応・成果・課題 | shared/researchと時点付き調査記録 |
| 演習・更新 | 問題、回答、フィードバック、共同検討、改善 | sessions、learning |

信頼性の高い情報を優先し、事実・企業の主張・推測・仮定を区別する。時点が変わる情報を固定知識として無期限に使わない。

特に、必要になったときに素早く調べて本人へ共有できる「パス」を作ることを重視する。事前知識に加えて、どの一次情報へどう到達し、何を確認してどう短く共有するかを整備する。

## 記録・編集・表示の確定ルール

- 編集ルートはGitHubのinterview-support/と[Notionホーム](https://app.notion.com/p/423161f2809781ff9677d9f3c6a9e488)配下。拡張可、領域外は勝手に編集しない。
- GitHubはCodex用の詳細な正本、Notionは本人向けの最新の確定事項・エッセンス・構造の可視化。
- 現行確定、議論の過程、過去、未決定の案を別レイヤーにする。正確・過不足なく・重複を抑え、節目ごとに細かく保存する。
- Notionは視覚から構造を捉えられるよう、図・フロー・表・箇条書き・必要なイラストを使う。最新情報を上に、詳細は子ページへ。
- 指示済みの調査・整理・文書更新・学習・支援に追加承認を求めない。まだ行わないと明示された作業は開始しない。

## 現在の実施状態

| 状態 | 内容 |
| --- | --- |
| 整備済み | 目的、保存先、モードの境界、運用文書、記録構造、新チャットの入口 |
| 今後策定 | 各モードの具体的な解法・対話手順・回答の長さと形式・応答速度と確認のバランス・前提と計算の保持方法・評価基準 |
| 未着手・今回実施しない | Web情報収集、会員サイト利用、知識・施策例の収集、問題演習・実測評価 |

入口の整備と、支援手順の完成・実践検証済みを区別する。
