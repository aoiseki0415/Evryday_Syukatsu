# コンサルの一般構造：4概念

状態：本人との議論で用語・比較枠組みを整理済み。各図の重み・記号は比較用の仮説であり、業界統一規格・案件統計ではない。原資料は[Notion「コンサルの構造化」](https://app.notion.com/p/40f161f280978009a9a0f7ba92ea2381)。

## 1. 4概念を分ける

| 概念 | 問い | 今回の定義 |
| --- | --- | --- |
| 変革の対象範囲 | どこを変えるか | 全社・事業・部門・業務 |
| 支援領域 | 何のテーマ・専門性で支援するか | 戦略、Operations、Technology、AI・データなど |
| 企業カテゴリー | 何を中核に支援する会社か | 戦略コンサル・総合コンサル・ITコンサル・SIer |
| 支援工程 | 変革のどの段階を担うか | ①方針・構想策定、②設計、③導入・実行、④定着・運用・改善 |

対象範囲を一つの軸として、支援領域ごとに扱う対象の重心を見る。企業カテゴリーは支援領域と工程の重心に関連する。カテゴリーだけで案件・個人の仕事を一対一に決めない。

Strategy → Operations → Technologyは工程の順番ではない。Operationsは事業を動かす仕組み・プロセスの領域で、単に「実行段階」という意味ではない。Technologyにも構想・方針策定がある。

## 2. 変革の対象範囲

| 対象範囲 | 見る対象 |
| --- | --- |
| 全社 | 会社・複数事業を横断する方針・仕組み・組織・共通基盤 |
| 事業 | 特定事業の顧客価値、収益モデル、競争や運営の仕組み、新規事業 |
| 部門 | 営業・製造・経営企画・人事・経理などの機能・部門 |
| 業務 | 個別の仕事や一連のプロセス |

複数部門をまたぐ業務もあるため、必ずしも厳密な組織階層ではない。予算・人数・重要性の大小とは別。本人は、広い対象範囲をインパクトの大きさを見る目安とし、全社レベルで変えられる仕事に魅力を感じている。ただし広ければ実際の価値が必ず大きいという外部事実ではない。

全社Operationsの例は、本社・事業部の役割、共通業務、拠点・供給体制の設計。全社の技術運用も、個別業務の構想策定もあり、工程と対象範囲は別に見る。

## 3. 支援領域

| 領域 | 主に扱うテーマ |
| --- | --- |
| 戦略 | 企業の舵取り、方向性、競争、投資・資源配分 |
| オペレーション | 調達・生産・物流・サービス等の仕組み・プロセス |
| テクノロジー | IT方針、システム構成、技術基盤 |
| AI・データ | データ、分析、モデル、AI活用・基盤・管理 |
| 組織・人材 | 組織、権限、人材配置・育成・評価 |
| マーケ・営業 | 顧客、ブランド、価格、販路、営業の仕組み |
| 財務・経理 | 資金調達、資本配分、経営管理、会計 |
| リスク・法令対応 | リスク管理、規制、内部統制 |
| サステナビリティ | 環境・社会への対応、持続可能な事業 |

「経営」は意味が広いため、企業の舵取りという支援領域の名称は「戦略」を維持した。領域は重なる。戦略コンサルの会社分類と、支援領域「戦略」は同じ概念ではない。

## 4. 支援工程

| 工程 | 支援領域に共通する内容 | システム系なら |
| --- | --- | --- |
| 1 方針・構想策定 | 上位方針と現状を踏まえて目的・対象・方向性を定める。必要なら戦略自体を見直す。 | IT戦略、システム化構想、対象範囲・優先順位 |
| 2 設計 | 条件・構成・役割・手順を設計する。 | 要件定義、システム設計。基本・詳細設計を別の共通工程にはしない。 |
| 3 導入・実行 | 設計したものを形にし、実際に動かし始める。 | 開発・設定、テスト、移行、本番導入 |
| 4 定着・運用・改善 | 現場に定着させ、継続して機能させながら改善する。 | 利用者教育、運用・保守、効果検証、追加改修 |

上位の経営・事業方針を今回の対象へ落とすことは①に含む。必要な場合は方針自体を見直す。毎回全社戦略をゼロから策定するわけではない。工程は往復・反復しうる。②と③は「設計する／形にして実行する」で分け、要件定義をITだけの共通工程名にはしない。

## 5. 企業カテゴリー

- **戦略コンサル**：一般図では領域「戦略」の①〜④と、他領域の①を軸に置く。領域によって①の重みも異なる。専門組織が他領域の②〜④を担う例もあり、非対応とはしない。
- **総合コンサル**：複数領域の構想・設計から導入・定着まで。全領域・全工程を一律に最も強いとはしない。IT・AIの実装・運用は企業・部門差を残す。
- **ITコンサル**：ITの構想・方針、業務・システム設計を中核とし、導入管理・定着や直接開発・運用も企業によって行う。
- **SIer**：設計・開発・統合・本番運用を中核とする。構想・戦略を扱う部門もある。

ITコンサルとSIerを合わせる中間案があったが撤回し、4分類に戻した。違いを見る際には工程と、そこで何を担うかを見る。

## 6. 一般図の保存と、AI限定図との関係

一般Aは「企業カテゴリー ×［横に支援領域 → 各領域内で縦に4工程］」という入れ子。一般Bは「対象範囲 × 支援領域」。9領域×4工程×4カテゴリーと、4対象範囲×9領域の記号は[framework.json](framework.json)に保存。

記号は頻度の統計ではなく概念整理の目安。全社・部門が強いのに事業だけ弱いとした一部のセルは、本人の指摘で連続したイメージに修正した。

一般図のAIセルは一般化した初期仮説。後続のAI限定のA・Bは、①への共通仮定や実装・継続関与の調査を加えた別の比較。[最新AI比較](ai-current-state.md)と混同しない。一般図の記号から最新AIの結論を逆算しない。
