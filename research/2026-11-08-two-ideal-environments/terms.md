<callout icon="📘" color="blue_bg">
<b>この整理では「AI変革支援」を共通の呼称にする。</b>

顧客企業がAIを活用して事業・業務・組織等を変えることを、構想・設計から導入・実行、定着・運用・改善まで支援する仕事。AIを使う主体は顧客企業。
</callout>

## 1｜仕事・目標の呼び方

| 統一する用語 | この整理での意味 | 表現の使い分け |
| --- | --- | --- |
| <b>AI変革支援</b> | 議論の対象である仕事の全体 | 「AI導入支援」「AI活用支援」を含む総称 |
| <b>技術導入</b> | AIシステム・モデル・基盤を業務へ組み込む活動 | 変革支援の中の技術的な活動を指すときに使う |
| <b>AI・データ</b> | 支援領域の一つ | 企業・職種の正式名称は原表記を保つ |
| <b>AIアーキテクト</b> | 技術の可能性・限界を踏まえ、AI活用の全体構成と実現方法を設計する役割 | 本人の到達像。正式な新卒職種名と同一とは限らない |
| <b>今後求められるAI変革支援</b> | 各社の記事・外部評価から考える、今後さらに重視されると考えられる支援 | 将来の提言・予測を含む。確定した未来ではない |
| <b>目指す支援像</b> | 本人の志向と今後の必要性を統合した、自分が担いたい支援 | 05で具体化する |
| <b>志望先の条件</b> | 目指す支援を経験できる環境を選ぶ基準 | 条件そのものと、確認に使う情報を分ける |

この用語集は、今回の議論を読みやすくするための定義。業界共通の資格・職種体系を新たに定めるものではない。

## 2｜業界を見る4要素

| 用語 | 問い | 統一する区分 |
| --- | --- | --- |
| <b>変革の対象範囲</b> | どこを変えるか | 全社／事業／部門／業務 |
| <b>支援領域</b> | どんなテーマ・専門性で支援するか | 戦略／オペレーション／テクノロジー／AI・データ／組織・人材等 |
| <b>支援工程</b> | 変革のどの段階に関与するか | ①方針・構想策定→②設計→③導入・実行→④定着・運用・改善 |
| <b>企業カテゴリー</b> | どんな領域・工程を中核とする会社か | 戦略コンサル／総合コンサル／ITコンサル／SIer |

<callout icon="🧭" color="gray_bg">
<b>「全社」は対象範囲、「戦略」は支援領域、「構想」は工程。</b>

全社の運用も、業務の構想もある。カテゴリーは重心を読む目安で、個人の仕事を決めるものではない。
</callout>

| 類似表現 | 今後使う表現・注意点 |
| --- | --- |
| 規模感・スケール感 | 対象範囲を指すなら「変革の対象範囲」。予算・人数・効果の大きさとは分ける |
| 上流・下流 | 原則として工程番号と工程名で書く |
| 実装・開発 | 技術を形にする③の活動。③には業務・制度の導入も含む |
| 要件定義 | システム系では②設計に含める。「用件定義」は使わない |
| 関与の深さ | 「関与の程度」。技術判断・実装参加・継続関与から見る |
| 一気通貫・全工程対応 | ①〜④を担う範囲。各工程への関与の程度や、個人の担当は別に確かめる |
| 内製・自社完結 | 実施体制の特徴。外部パートナーを使うことだけで関与が弱いとは判断しない |

## 3｜企業の活動と、自分の可能性

<b>AI活用を前提に再設計する領域</b>：AIそのものの使用先だけでなく、その活用に伴い変える戦略・業務・人材組織・基盤・統制。01の「支援領域」と同じ専門性が関係するが、ここでは顧客企業側で再設計する内容を指す。

<b>理想の企業像①②</b>：05で定めた二つの環境条件。①幅広い専門性と協働、②AI技術力と構想・実装の接続。06の現行比較はこの二条件を使う。

| 用語 | 確かめたいこと |
| --- | --- |
| <b>企業の活動</b> | 会社・部門が実際に何を担うか |
| <b>構想と実装の接続</b> | 同じ案件・目標・意思決定の中で①と②〜④がつながるか |
| <b>本人の関与可能性</b> | その接続や若手の仕事から、自分も関われそうかを間接評価したもの |
| <b>全社変革</b> | 複数部門・事業の業務、組織、意思決定、資源配分等を変えること |
| <b>全社共通基盤</b> | 会社全体で使うAI・データ・システム基盤。全社変革へどうつながるかを別に見る |
| <b>ガバナンス（統制）</b> | 誰が何を判断・実行し、どの権限・責任・監視・是正の下で運営するかを定める仕組み |

「本人の関与可能性」は配属・担当の保証ではない。別部門の専門家と協働する環境も含める。

## 4｜根拠・判断・募集の表記

| 表記 | 意味 |
| --- | --- |
| <b>確認事実</b> | 公式資料・案件・募集本文などに明示されている内容 |
| <b>外部の見解</b> | 記事の提言やIDCの評価。客観的な確定法則とは分ける |
| <b>統合判断</b> | 志向と複数の根拠を照合したCodexの解釈・推薦 |
| <b>候補環境</b> | 企業×部門・専門組織×職務・役割。正式募集職種とは別欄 |
| <b>志望先</b> | 本人が選んだ企業・部門・職種。調査上の推薦だけで確定しない |
| <b>国内新卒入口</b> | 日本の大学・大学院新卒が応募できる制度・経路 |
| <b>28卒対象</b> | 2028年卒向けと確認した要項・プログラム |
| <b>現在受付</b> | 確認日に申込受付が確認できること。プレ登録・インターン・本選考を分ける |
| <b>配属の確かさ</b> | 希望部門・専門職への配属がどの程度明示されているか |
| <b>未確認</b> | 今回の公開情報では判断できない。「存在しない」「不適合」とは区別する |

用語・役職・職種の公式名称や、原文の引用を統一用語で書き換えない。説明文の呼称をそろえる。

## 5｜略語の使い分け

| 表記 | 意味・この整理での使い方 |
| --- | --- |
| <b>データサイエンス</b> | 統計・機械学習等でデータから知見・モデルを作る専門性。説明文では略さない |
| <b>Deployment Strategist（DS）</b> | デロイトの価値構想・展開を担う役割表記。Data Scientistとは別 |
| <b>FDE</b> | Forward Deployed Engineer。顧客に近い場で技術を実装する役割。具体職責は会社ごとに確認 |
| <b>RDE</b> | アクセンチュアのReinvention Driver & Engineerという到達像。独立した新卒募集職種名ではない |
| <b>PoC（概念実証）</b> | 実現性・有効性を検証する段階。本番導入とは分ける |
| <b>本番導入</b> | 実際の業務・利用環境で稼働させること。全社展開完了とは別 |
| <b>COE</b> | AIを横断的に推進する専門組織。設置だけで顧客の自走を証明しない |
| <b>MLOps／LLMOps</b> | モデル・生成AIの評価、監視、更新等を継続する仕組み |
| <b>AIエージェント</b> | 目標に応じてツール等を使い判断・実行する仕組み。自律性・許可範囲を個別に確認 |
