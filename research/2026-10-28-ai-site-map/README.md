# 5社の公式サイト：AI・データ関連ページの探索記録

調査日：2026年10月28日。対象はデロイト トーマツ、EYジャパン、PwCジャパン、KPMGジャパン、アクセンチュア。

## 目的と読み方

日本語トップから同じ企業の公式サイト内をたどり、AI・データ関連の発信量と情報の配置を把握する。今回の件数は**取得できたページをルールで関連判定したURL数**であり、全サイトの総数や全記事の精読数ではない。記事本文の全文保存・転載はしない。

本人の希望に従い、今回の比較ではページの多さを「AI・データへの関心・発信の厚み」の指標として見る。職種・部署の採用難易度、実装力、業務配分、売上、配属確約を示す数値にはしない。日本語トップを起点とするが、国内法人だけの集計ではなく、そこからつながる同社の海外・グローバルサイトを含む。

最初に[サイト地図と読む順番](GUIDE.md)を読む。各社の全URLは下記の索引、機械検索は `inventory.jsonl` を使う。

- [PwC](pwc.md)
- [KPMG](kpmg.md)
- [アクセンチュア](accenture.md)

## 起点と探索範囲

最初に日本語で各社名を検索して日本語トップを確認した。検索結果に出た個別記事を直接件数へ足すことはせず、起点からのリンク経路があるURLを対象にした。

| 会社 | 日本語トップ | 許可した公式ドメイン |
|---|---|---|
| デロイト トーマツ | https://www.deloitte.com/jp/ja.html | deloitte.com、deloitte.jp と配下 |
| EYジャパン | https://www.ey.com/ja_jp | ey.com と配下 |
| PwCジャパン | https://www.pwc.com/jp/ja/ | pwc.com と配下 |
| KPMGジャパン | https://kpmg.com/jp/ja.html | kpmg.com、kpmg.or.jp、kpmg-consulting.jp と配下 |
| アクセンチュア | https://www.accenture.com/jp-ja | accenture.com、accenture.jp と配下 |

- 同じ企業の公式ホストに限定し、他社・外部メディア・SNSへ移動するリンクは追わない。外部ドメインへの転送も追わない。自社ホスト上にある第三者評価レポートは含む。
- トップから**探索時の親リンクを最大6回**たどる範囲で探索。サイト内検索の検索件数やGoogleの概算ヒット数は使っていない。
- AI／データ関連語を含むリンク・リンク周辺文、関連ページのPDFダウンロードを追う。最初の2段はサービス、インサイト、ニュース、採用などの一般入口も通過する。通過しただけの一般ページは関連数へ加算しない。
- `depth` は記録されたリンク網での最短到達段数。URLのスラッシュ数ではなく、リンクを何回たどるかを示す。別経路が後から見つかるため、探索時の段数より小さくなる場合がある。
- HTMLとPDFを対象にし、PDFは1 URLを1ページとして数える。画像、動画・音声ファイル、Office添付は対象外。PDF内の同社URLも追った。
- 本文を自動抽出できないページ、アクセス拒否、未取得の先のリンクは集計に含めない。JavaScriptで後から読み込まれる一覧、ボタン操作、ログイン・登録後の記事は取り切れていない。
- アクセンチュアは国指定URL等のHTTP 403が多い。トップも再取得時に403となったが、Web閲覧で日本語トップと公式ニュースルームへのリンクを再確認した。補助的な経路証拠は `manual-route-evidence.json` に記録した。

## 関連性と4分類

関連性は、タイトル／主見出し、概要と本文、最終転送先のURLと本文、PDFの冒頭と本文を照合して判定した。サイト共通メニューだけの「AI」、一般ページへ移転した旧AI記事、エラーは除外する。AI・データを重要な一論点として扱う業界調査やサービスも含む。AI・データ利活用に関わるデータ管理、AI監査・リスク、関連する採用・専門家紹介も範囲に含む。

| 分類 | 含む内容 |
|---|---|
| 1 技術・データ基盤 | アーキテクチャ、RAG、LLM、モデル・アルゴリズム、データ基盤、データサイエンス等を主題とする解説・サービス |
| 2 導入支援・活用事例 | 個別サービス、実装・導入、企業や業務への活用、顧客事例 |
| 3 経営・業界動向・調査 | 経営・市場・業界への影響、調査報告、インサイト、その他のAI発信 |
| 4 ガバナンス・人材・組織 | 信頼、倫理、リスク、規制、人材育成、働き方、専門家・インタビュー・採用 |

各URLを主分類1つに置き、複数の論点は `topics` に併記する。タイトルを優先する簡易分類なので、**技術を本文で説明していても、事例・人材・調査の分類になることがある**。「分類1の件数＝技術内容を含む全ページ数」とは解釈しない。代表ページは見出し・概要・一部本文を人手相当で確認し、`review-overrides.json` に補正を記録した。それ以外は自動抽出・ルール分類であり、誤分類や関連範囲の境界に誤差を含む。

URLはクエリ文字列、国・言語、新旧パスが違えば別に数える。ページ内アンカー（`#...`）だけの違いは同じページとして扱う。比較の補助としてクエリ除去後、転送先統合後の数も出すが、翻訳・転載・同内容の完全重複排除を意味しない。

## 保存ファイル

| ファイル | 用途 |
|---|---|
| `GUIDE.md` | 企業ごとの情報配置、代表経路、次のES・面接準備での使い方 |
| `inventory.jsonl` | 全関連URLの統合索引。会社、タイトル、主分類、テーマ、言語、形式、親URL、到達段数、取得日時、内容ハッシュ |
| 各社 `.md` / `.csv` | 人向けの一覧／集計・再利用向けの同じ索引 |
| `summary.json` | 件数・分類・言語・形式・到達段数・未取得数 |
| `routes.csv` | 関連ページにたどり着くための親子リンク。必要な一般入口だけを補助的に含む |
| `crawl-audit.csv` | 取得を試みたURL、HTTP状態、関連判定、除外理由。一般ページを件数に混ぜていないことの監査用 |
| `unconfirmed.csv` | 取得失敗／探索範囲の先に残る未取得リンク。関連性は未確認、件数に含めない |
| `review-overrides.json` | 代表ページの確認と分類・表示タイトルの補正 |
| `manual-route-evidence.json` | Web閲覧で補完したトップからのリンク証拠 |

取得本文・大きな生のリンク網は一時領域だけに置き、公開GitHubには転記しない。CSV・JSONLには短い書誌情報とURLを残す。今回の調査は公開ページのみを参照し、Notionの変更はしていない。

## 後続チャットと再実行

1. `GUIDE.md` → 各社索引の順に読み、`rg 'RAG|アーキテクチャ|医療' research/2026-10-28-ai-site-map/inventory.jsonl` のように探す。
2. 気になるページを原サイトで再読する。日付、法人、部署、顧客案件／社内利用、実装済み／構想を確認してからES・議論に使う。
3. 件数や採用情報を現時点の事実として再利用するなら、改めて確認する。今回の件数は2026-10-28の探索スナップショット。

補助コードは `scripts/ai_site_map.py` と `scripts/build_ai_site_index.py`。Python、lxml、pypdf、curlを利用する。初回は `ai_site_map.py all --maxdepth 6 --limit 6000`、一時キャッシュが残っている場合のみ `--refresh` で再判定できる。出力索引は `build_ai_site_index.py` で生成する。ネットワーク接続は実行環境の権限に従う。一時キャッシュが消えた場合も、GitHubのURL・経路・分類の記録は残る。
