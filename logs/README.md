# 議論と操作の記録ルール

## 目的と保存先

- `HANDOFF.md` は**現在地**。別チャットが短時間で再開できるよう、確定方針、未決定点、次の行動、最新ログへのリンクだけを維持する。
- `logs/YYYY-MM-DD-内容.md` は**経緯**。意思決定の理由、見送った案、重要な新情報、Notion操作の結果を、話題ごとに記録する。同じ話題を同日に続けた場合は既存ログを更新し、空の日次ログは作らない。
- `就活戦略_現状整理.md` はNotion資料からの暫定的な理解。新しいユーザーの発言や決定と矛盾したら、現在の決定を優先して修正する。
- Notionは人が読む現行方針・比較・合意済みの結論を置く場。GitHubの操作ログをそのまま転記しない。編集は、ユーザーが指示した内容、またはこの記録運用で合意した結論の要約に限る。保存先は就活ワークスペース内の適切な既存ページを優先する。

## 記録する契機

作業の終わりまでに記録するのは、就活の判断軸や候補が変わったとき、決定・撤回・保留が生じたとき、共有資料から重要な知見を得たとき、Notionのページ・データベースを編集したとき。短い確認、既出事項の反復、変更のない雑談は記録不要。

## 各ログに残す内容

1. 日付と話題。ユーザーの発言、Notionページ、資料などの出典。
2. **決定済み／検討中／過去の見解**を分けた結論と理由。選ばなかった案が重要ならその理由。
3. 残る論点と次の行動。期限があるなら根拠を確認した日付。
4. Notionを操作した場合、対象ページ、指示された変更、実施内容、読み戻しによる確認結果。未実施・未確認なら明示する。

## 各タスクの終了前

1. `HANDOFF.md` を最新の決定と次の論点に合わせて更新する必要があるか確認する。
2. 記録対象の議論や操作があればログを更新する。根拠へのリンクを付け、推測を確定事項として書かない。
3. リポジトリのルートと `origin` が `aoiseki0415/Evryday_Syukatsu` であることを確認し、関連ファイルだけをステージする。`git diff --cached --check` と差分を確認してコミット・pushし、remoteの反映を確かめる。無関係な `.DS_Store` などは触らない。
4. Notion編集後は対象を読み戻す。ログとチャットで、確認できた結果と未確認の部分を区別する。

認証情報、マイページID、社内資料、機密情報、長い個人メモの原文はGitHubに置かない。必要な根拠はNotionへのリンクと簡潔な要点で示す。この記録は会話・作業に付随して行い、新しい定時自動化は作らない。
